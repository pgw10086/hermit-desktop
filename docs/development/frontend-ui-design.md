# 前端 UI 设计规范

状态：`current`

本文是 Hermit 前端布局、信息层级、交互反馈和组件复用规则的唯一权威来源。DSH 接入、
Product Plugin 组件所有权和资格流程见
[Product Plugin UI 规范](../../plugins/ui-guidelines.md)；具体业务流程由对应 `DESIGN.md`
负责。

## 基本原则

- DSH Web 是产品工作面的视觉宿主。优先使用其公开组件、图标、主题和交互能力，不复制
  shell，也不建立外观相似的第二套设计系统。
- 首屏直接服务用户的主要任务。辅助信息按需出现，不用欢迎页、装饰卡片或空面板填充页面。
- 原型验证真实布局和交互，使用正式项目允许的组件与边界；不得另画一套只能展示、不能迁移
  的页面壳。

## Flux 布局

这里的 Flux 指状态驱动的流动布局，不是前端状态管理框架：页面结构由当前可见区域、内容
状态和可用空间共同决定。

```text
普通状态： [导航] [业务列表] [主内容] [可选辅助区]
收起导航：        [业务列表] [    主内容    ] [可选辅助区]
无辅助内容：      [业务列表] [        主内容        ]
专注状态：                    [主内容]
```

- 面板关闭后退出布局并释放空间，不能只隐藏内容而保留空列。
- 没有内容的可选区域默认不渲染；主内容自动扩展，不显示空辅助栏。
- 窗口变窄时优先保留主任务，依次收起低优先级区域；不能让文字、工具栏或固定格式控件重叠。
- 重新打开区域时恢复合理的先前状态；切换普通/专注入口不能复制业务数据或编辑状态。
- 固定格式区域使用 `minmax`、Grid/Flex 和明确的最小/最大尺寸。视口变化只调整布局，不按
  视口宽度缩放字体。

## 信息与操作层级

- 一个工作面只有一个主要任务和一个主要内容区。标题、筛选和主要动作保持紧凑。
- 高频动作靠近作用对象；低频动作进入菜单、详情区或操作流程，不在多个位置重复入口。
- 列表只展示识别和决策所需的信息；状态放在最接近受影响内容的位置。
- 空、加载、部分成功、错误、无权限和不可用状态必须有明确结果。Toast 只提示短暂结果，
  不能替代需要处理的持久状态。
- 危险或不可逆操作说明影响范围和可撤销性；普通可恢复操作不增加无意义确认。

## 组件与视觉

组件选择顺序固定为：

```text
宿主公开组件 -> Hermit 已批准的共享组件 -> 原生语义 HTML -> 业务领域组件
```

- 只有前面三层不能表达真实业务能力时，才创建领域组件；不能重新制作 Button、Input、
  Modal、Menu、Tooltip、Toast 或已有图标。
- 业务列表、文件树、编辑器等领域组件留在所属模块。可稳定复用且不含业务语义的能力才进入
  共享 UI 包。
- 颜色、字体、间距、圆角、阴影和明暗模式跟随宿主 token 与组件，不复制数值建立产品调色板。
- 页面使用连续工作面、清晰分隔和紧凑层级。避免卡片套卡片、装饰性大标题、厚重阴影和无
  业务含义的视觉容器。
- 图标按钮使用官方语义图标并提供可访问名称；文本按钮只用于清晰命令。

## 组件职责与拆分

- 组件按业务责任、状态 ownership、真实复用、外部边界和可测试性拆分，不按固定行数或
  形式上的“纯展示”教条机械拆分。
- Product Surface/page 负责页面编排和跨区域状态；领域组件负责自己的局部交互状态；
  DSH/Hermit contract、RPC、storage 等外部边界通过明确的 adapter、hook 或 service 访问。
- Canonical 业务状态只能有一个 owner；子组件不能偷偷维护第二份副本，也不能为了减少
  props 直接读取无关的全局状态。
- 简短、只使用一次且与父级高度耦合的 UI 不必拆分；不为了预期中的未来复用创建浅层 wrapper。
- 跨插件复用的组件必须不含业务语义，并经过公共职责、Props、状态、可访问性和维护成本
  评估，不能逐步演变成第二套设计系统。

## 交互与响应

- 鼠标与键盘可以完成关键命令；焦点进入、返回、Escape、快捷键冲突和 overlay 关闭行为明确。
- 长中文、窄窗口、200% zoom、空数据和大量数据不能造成遮挡、跳动或操作不可达。
- 展开、收起、选择、编辑和保存状态由单一业务状态驱动，不能为不同入口维护重复副本。
- 宿主负责全局导航、窗口布局和 Product Surface；业务模块只渲染自己的内容区域。

## 原型与验收

- 可迁移的业务工作面与本地预览入口分离。预览入口只负责挂载、mock 数据和状态切换。
- mock 动作应对应未来公开 service，不接真实用户数据、文件系统或私有宿主状态。
- 视觉验收使用 `tabbit-cli` 驱动真实页面并检查截图；DOM 和尺寸断言只能辅助，不能代替
  实际图片判断。
- 验收真实流程、状态转换、可访问性和布局释放；不以颜色、padding、README 或大面积截图
  snapshot 作为自动测试目标。
- 新增 UI 前先确认现有公开能力。确有缺口时记录缺口、职责和归属，再补最小组件。
