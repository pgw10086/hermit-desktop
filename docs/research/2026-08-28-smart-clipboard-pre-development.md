# Smart Clipboard 开发前主资料调研

日期：2026-08-28

状态：调研结论，不是当前实现或产品规范。Smart Clipboard 的产品事实仍以
`plugin-smart-clipboard` sibling 仓库中的 `DESIGN.md` 为准；本文件只记录
一手证据、差距和建议 Gate。

## 结论

**当前不应直接开始完整 TEXT vertical slice。** 可以开始的只有三个有明确退出条件的资格
工作：DSH Product Surface、最小 Core capability seam、packaged macOS clipboard 行为。

原因不是未来扩展，也不是需要先建设通用插件平台，而是第一条切片自己的两条入口还未成立：

1. **[VERIFIED]** 当前冻结的 DSH `0.1.1-rc.2` 公开 Client contract 没有适合 Smart
   Clipboard History 的“可追加全局导航入口 + 插件持有持久业务页”Product Surface。
2. **[VERIFIED]** 当前 Electron 主流程没有挂载 Quick Panel、全局快捷键、锁屏 UI 处理或
   ClipboardBridge；M1 也明确没有实现完整 Capability Broker。
3. **[VERIFIED]** Apple 已发布 General pasteboard 的 Access Behavior API 契约，本机 SDK
   也包含该 API；**[UNKNOWN]** 当前 macOS 26.6.2 是否会对 packaged Hermit 实际执行提示、
   allow/deny 和读取阻断尚未实测。Hermit 不能仅凭 API 声明承诺 ACTIVE 后一定无提示、无阻塞。
4. **[VERIFIED]** 同一插件 artifact 在 stock DSH / Hermit 双端加载、React 单实例和以重启
   为边界的停用/移除已经通过；这只够证明插件骨架，不够证明 Product Surface 或剪贴板能力。
5. **[INFERENCE]** 自动粘贴失败不是首切片的硬阻塞，因为既有设计已经把“先写回剪贴板，
   再 best-effort 粘贴，失败时 copy-only”定义为正常降级；真实写回仍必须通过平台资格。

因此当前裁决是：

- `READINESS_AND_FOUNDATION_QUALIFICATION = GO`
- `TEXT_DOMAIN_IMPLEMENTATION = NO-GO`
- `PRODUCT_SCOPE = FROZEN` 不受本调研影响
- `READY_FOR_IMPLEMENTATION` 只能理解为业务范围已冻结，不能理解为外部技术 Gate 已满足

## 证据标记

- **[VERIFIED]**：由官方文档、官方源码、冻结 lock、实际 package 类型或已有资格 artifact
  直接支持。
- **[INFERENCE]**：由多个已验证事实推导出的工程判断，尚未经过目标成品实测。
- **[UNKNOWN]**：当前资料无法回答，必须通过 spike、原生平台测试或新的公开契约补证。

## Maccy 2.7.1 的真实行为

本节以 2026-08-28 官方 latest release `2.7.1` 为比较基线。Maccy 是行为参考，不是 Hermit
的 UI、数据库、配置或平台实现来源。版本证据见
[Maccy Releases](https://github.com/p0deje/Maccy/releases/tag/2.7.1)，日常键盘交互见
[官方 README](https://github.com/p0deje/Maccy/tree/2.7.1#usage)。

| 主题 | 官方实现事实 | 对 Hermit 的含义 |
| --- | --- | --- |
| 捕获 | **[VERIFIED]** 用定时器比较 `NSPasteboard.changeCount`，默认间隔 `0.5s`；仅变化后读取 pasteboard items 和 representations。见 [`Clipboard.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Clipboard.swift) 与 [`Defaults.Keys+Names.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Extensions/Defaults.Keys%2BNames.swift)。 | 可借鉴“变化检测后再读取”的行为，不应把轮询、AppKit 或 `changeCount` 写进跨平台 domain。 |
| 支持类型 | **[VERIFIED]** 稳定版读取 file URL、HTML、PNG、RTF、String、TIFF；一个 copy event 的多个 item/representation 会合并成一个 history item。 | Hermit 的 `TEXT / IMAGE / FILE_LIST` 是自己的 canonical 分类，不是照搬 Maccy 的 PasteboardType 表。 |
| 忽略 marker | **[VERIFIED]** 在读取 payload 前跳过 `AutoGeneratedType`、`ConcealedType`、`TransientType`，并支持额外 ignored types/app/regexp。marker 字符串由 Maccy extension 定义，见 [`NSPasteboard.PasteboardType+Types.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Extensions/NSPasteboard.PasteboardType%2BTypes.swift)。 | 首切片应在读取正文和持久化前检查这些明确 marker；不能把它们表述为 Apple 提供的标准常量，也不能假定 Windows/Linux 有同名 marker。 |
| 去重 | **[VERIFIED]** `HistoryItem.supersedes` 忽略一组瞬态 metadata 后比较 representation 的 type/value；命中时新对象继承旧对象的首次复制时间、次数、pin/title，并删除旧存储对象。见 [`HistoryItem.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Models/HistoryItem.swift) 和 [`History.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Observables/History.swift)。 | Hermit 已冻结的 UTF-8 精确 hash、稳定 ID 和 `last_used` 规则是 Hermit 自己的契约，不能宣称与 Maccy 数据语义完全相同。 |
| 搜索 | **[VERIFIED]** 支持 exact、fuzzy、regexp、mixed；默认 exact 为大小写不敏感 substring；UI 侧使用 `0.2s` throttle。见 [`Search.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Search.swift) 和 [`History.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Observables/History.swift)。 | 首切片只做已冻结的普通本地文本搜索即可，不需要为了“Maccy-like”提前加入 fuzzy/regexp/mixed。 |
| 键盘执行 | **[VERIFIED]** 默认快捷键呼出；输入搜索；Enter/点击/编号选项执行复制；Option+Enter 尝试粘贴；Option+Shift+Enter 无格式粘贴；Option+P 置顶。 | Hermit 已确认的可配置 Enter/Mod+Enter/Shift+Enter 映射是自己的交互，行为目标相似但不必复制按键。 |
| 自动粘贴 | **[VERIFIED]** 先写 NSPasteboard，再通过 `CGEvent` 发送 paste chord；在此之前检查 Accessibility trust。 | 复制和自动粘贴是两个结果；权限拒绝或目标应用不接受模拟输入时必须报告 copy-only，不能回滚已经成功的剪贴板写入。 |
| 来源应用 | **[VERIFIED]** Maccy 在检测变化时读取 `NSWorkspace.shared.frontmostApplication`。Apple 只把它定义为“当前接收键盘事件的 app”。 | **[INFERENCE]** 来源应用只能是 best-effort attribution，不是剪贴板写入者的可证明 provenance；异步 copy、焦点切换和远程桌面可产生误归因。 |
| 历史限制 | **[VERIFIED]** 2.7.1 默认普通历史 `200` 条，设置范围 `1...999`；limit 只清理 unpinned。设置页展示数据库大小，但稳定源码没有 Hermit 所定义的 1 GB quota 或按时间过期规则。见 [`Defaults.Keys+Names.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Extensions/Defaults.Keys%2BNames.swift) 与 [`StorageSettingsPane.swift`](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Settings/StorageSettingsPane.swift)。 | Hermit 默认 100 条、1 GB、可选时间期限是自己的产品规则，不应归因给 Maccy。 |

## 平台能力矩阵

### macOS

| 能力 | 结论 | 证据与限制 |
| --- | --- | --- |
| 后台变化检测 | **[VERIFIED]** AppKit 暴露 `NSPasteboard.changeCount`，所有权变化时递增；官方没有提供与 Windows listener 等价的通用 change event。 | [Apple `changeCount`](https://developer.apple.com/documentation/appkit/nspasteboard/changecount)。Maccy 的稳定实现是定时比较。检测变化与成功读取 payload 必须是两个状态。 |
| 多 item/representation | **[VERIFIED]** 一个 pasteboard 可包含多个 item，每个 item 可有多种 representation。 | [Apple `NSPasteboard`](https://developer.apple.com/documentation/appkit/nspasteboard)。首切片应只抽取明确的 TEXT representation，不把整个 native 对象泄露给 Product Plugin。 |
| 程序化读取权限 | **[VERIFIED]** Apple 的 AccessBehavior API 契约定义 General pasteboard 的 `.default` 为 programmatic access 时 ask，并允许 `.ask`、`.alwaysAllow`、`.alwaysDeny`；本机 SDK header 标记 API 自 macOS `15.4` 可用。 | [Apple `AccessBehavior`](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum)。**[UNKNOWN]** API 可用不等于已观察到当前系统强制；[Apple AppKit updates](https://developer.apple.com/documentation/updates/appkit) 在 2025-04 条目中仍称其为 upcoming feature，并给出 developer preview 开关。当前目标机是 macOS `26.6.2 arm64`，必须用 packaged Hermit 分别实测默认环境与显式 preview 环境下的提示、状态读取和 deny 后 payload 行为。 |
| 写回剪贴板 | **[VERIFIED]** AppKit 与 pinned Electron 43 都可写文本和原生 format。 | [Electron clipboard](https://www.electronjs.org/docs/latest/api/clipboard)；冻结版本实际能力以本地 `electron.d.ts` 为准。 |
| 自动粘贴 | **[VERIFIED]** Core Graphics 可以向 event stream post Quartz event；Accessibility API 可查询当前进程是否 trusted，提示是异步的。 | [Apple `CGEvent.post`](https://developer.apple.com/documentation/coregraphics/cgevent/post%28tap%3A%29)、[`AXIsProcessTrustedWithOptions`](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)。API 存在不等于目标应用一定接受输入。 |
| 锁屏检测 | **[VERIFIED]** Electron `powerMonitor` 提供 macOS/Windows `lock-screen`、`unlock-screen`。 | [Electron powerMonitor](https://www.electronjs.org/docs/latest/api/power-monitor/)。**[UNKNOWN]** 锁屏期间 pasteboard 是否仍产生且允许读取预期内容，必须在 packaged app 上实测；lock event 只能证明可以隐藏 UI。 |
| 来源应用 | **[VERIFIED]** AppKit 只能直接给出当前 frontmost app，即当前接收 key event 的 app。 | [Apple `frontmostApplication`](https://developer.apple.com/documentation/appkit/nsworkspace/frontmostapplication)。**[INFERENCE]** 只能作为 best effort source identity。 |

需要修正一个实现措辞：如果去重定义为 TEXT UTF-8 bytes 的 hash，应明确为“对 Hermit
选定的纯文本 representation 精确解码，再按 UTF-8 编码得到的 bytes 计算”，期间不 trim、
lowercase、Unicode normalize 或改换行；不能声称拿到了来源应用最初写入时的原始 bytes。
AppKit 允许同一概念存在多种 representation。

### Windows

| 能力 | 结论 | 证据与限制 |
| --- | --- | --- |
| 变化监听 | **[VERIFIED]** 新程序应使用 `AddClipboardFormatListener` 接收 `WM_CLIPBOARDUPDATE`；sequence number 可用于比较，但官方明确不建议把它用于 polling loop。 | [Microsoft Using the Clipboard](https://learn.microsoft.com/en-us/windows/win32/dataxchg/using-the-clipboard)。 |
| 写回 | **[VERIFIED]** Win32 clipboard 与 Electron 都提供读写；多 format 需要按平台优先级处理。 | [Microsoft Clipboard Operations](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-operations)。 |
| 自动粘贴 | **[VERIFIED]** `SendInput` 受 UIPI 限制，只能注入到相同或更低 integrity；失败结果不能指出是否由 UIPI 导致。 | [Microsoft `SendInput`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。因此 copy-only 是必要产品状态。 |
| 来源应用 | **[VERIFIED]** `GetForegroundWindow` 只返回用户当前操作的前台窗口，并可能为 null。 | [Microsoft `GetForegroundWindow`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow)。**[INFERENCE]** 与 macOS 一样只能 best effort，不能证明 writer。 |

Windows 不阻塞 macOS 第一条切片，但在 Windows adapter 开工前必须单独验证 delayed rendering、
clipboard busy/retry 边界、marker 等价策略、锁屏和真实 UIPI 降级，不能复用 macOS 结论。

### Linux：必须拆成 X11 和 Wayland

| 环境 | 结论 | 证据与限制 |
| --- | --- | --- |
| X11 | **[VERIFIED]** selection 内容由当前 client owner 维护，不是始终驻留在中央 server 中的普通数据对象。 | [Xlib Selections](https://www.x.org/releases/X11R7.6/doc/libX11/specs/libX11/libX11.html)。clipboard manager 需要处理 owner 生命周期和按需 conversion，不能直接套 Electron/macOS polling 心智模型。 |
| Wayland | **[VERIFIED]** `ext-data-control-v1` 能让 privileged client 管理 clipboard，但协议仍标记 staging/testing，且 compositor 支持不一致。 | [Wayland ext-data-control-v1](https://wayland.app/protocols/ext-data-control-v1)。 |
| XDG Portal | **[VERIFIED]** Clipboard portal 不创建一般剪贴板会话，只扩展 RemoteDesktop/InputCapture session，并受 session active 状态限制。 | [XDG Clipboard portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Clipboard.html)。它不能作为通用后台 clipboard manager 的现成 fallback。 |
| 全局快捷键 | **[VERIFIED]** Electron 在 Wayland 使用 desktop portal；注册结果与用户授权、portal identity 和 compositor 有关。 | [Electron globalShortcut](https://www.electronjs.org/docs/latest/api/global-shortcut/)。 |

**[UNKNOWN]** 当前没有足够一手证据承诺 Wayland 上跨 compositor 的持续后台捕获、来源应用识别
或通用自动粘贴。Linux 平台说明必须在 adapter 资格后按 X11/Wayland 分别发布支持结论。

## 当前 Hermit / DSH 实现是否足以支撑 TEXT slice

### 已经具备的基线

1. **[VERIFIED] 同一 artifact 双端基线已通过。**
   `.hermit/artifacts/dsh-reference-plugin-darwin-arm64.json` 记录同一个 reference plugin tarball
   在 stock DSH 和 Hermit bundled DSH 的 Host、Client bundle、Client UI、React Hook、disable、
   remove 均 PASS；候选是 DSH `0.1.1-rc.2`、Node `24.19.0`。
2. **[VERIFIED] React 单实例已通过真实 Hook。** reference Client externalize React/ReactDOM，
   双端执行真实 Hook 更新；权威说明见
   [`docs/contracts/dsh-integration.md`](../contracts/dsh-integration.md) 和
   [`packages/dsh-plugin-reference/README.md`](../../packages/dsh-plugin-reference/README.md)。
3. **[VERIFIED] Host effect 可回收。** 已有资格证明 Cordis fiber dispose 后 reference Host
   route 在同进程变为 404；这不能代替 Client UI 热卸载。
4. **[VERIFIED] 版本可追溯。** frozen lock 实际解析 Electron `43.4.0`、DSH
   `0.1.1-rc.2`、React `18.3.1`，见 [`pnpm-lock.yaml`](../../pnpm-lock.yaml)。

### 当前不具备的能力

#### 1. Product Surface 是当前硬失败，不是普通 unknown

**[VERIFIED]** pinned DSH package 的公开 slot 类型显示：

- `sidebar`、`conversation`、`details` 都是 `single`，且注释明确说明已被官方 UI 占用；
  再注册会替换整个官方列，而不是追加入口。
- `shell.overlay` 是唯一 root additive list，但定义为 frame-wide floating layer，不是持久业务页。
- Sidebar 内部的 `sidebar.workspaces` 与 `sidebar.settings` 都是已占用 `single`；
  `sidebar.footer.action` 是 footer 小动作位，不拥有产品页或导航状态。
- reference plugin 只注册 `settings.plugins.tab`；项目文档明确说 Settings 只是兼容探针，不能
  冒充 Product Surface。

本地可重建证据位于：

- `.hermit/runtime/dsh/node_modules/@deepseek-ai/dsh-client-ui-layout/lib/types/client/index.d.ts`
- `.hermit/runtime/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar/lib/types/client/contract/slots.d.ts`
- [`packages/dsh-plugin-reference/src/client/index.tsx`](../../packages/dsh-plugin-reference/src/client/index.tsx)

因此当前准确结论是：**DSH `0.1.1-rc.2` pinned public client contract 没有暴露适合 Smart
Clipboard History 的 additive root-level destination + plugin-owned persistent page。**

以下做法不能推翻结论：插件 private import、私有 Router、DOM/CSS 注入、覆盖 `single` occupant、
把 Settings 当业务页、用 `shell.overlay` 模拟持久主页面。经用户明确授权后，另有一条受控路径：
由 Hermit 为自带 DSH Web 携带 source-controlled、精确锁定的最小 source patch，并先把能力
做成公开 typed contract，再通过构建、license/notice、双宿主和生命周期资格。能推翻当前 rc.2
结论的证据包括：

1. 在同一 frozen artifact 找到此前遗漏、正式 public export 的完整 contract，并用标准第三方
   插件证明注册、导航、刷新恢复和生命周期；或
2. DSH 正式发布新的 public Product Surface，Hermit 升级 frozen DSH 后重跑 Reference Plugin、
   React 和 stock/Hermit 双端资格；或
3. Hermit 自带的 source-patched DSH generation 通过同等资格，且插件只依赖 patch 暴露的公开
   contract。

#### 2. Client 同进程热卸载当前明确不支持

**[VERIFIED]** pinned `@deepseek-ai/dsh-client-runtime` README 明确写明 `loader.unload` 是抛
not-implemented 的 stub，Client 没有从 fiber disposal 到 registration/style removal 的卸载链。
现有资格的 disable/remove 以重启 DSH 为生效边界；Host route 的即时撤销不能替代 Client UI。

首切片若接受当前边界，验收必须写成：privileged capture、shortcut 和 Host effect 在 disable
后立即停止；Client UI removal 依当前支持的 restart/reload boundary 验收。若产品硬要求点击
停用后当前页面内 UI 立即消失，则必须先升级 DSH lifecycle seam。

#### 3. Clipboard / shortcut capability 还没有接入主流程

**[VERIFIED]** 当前 `apps/desktop-vnext/src/main.ts` 没有挂载实验性的 `createQuickPanel`、
`QUICK_PANEL_IPC_CHANNEL` 或 `registerQuickPanelShortcut`；测试还明确锁定“M1 桌面壳不挂载待
独立设计的 Quick Panel”。`powerMonitor` 只接入 shutdown，没有 lock/unlock handler。

**[VERIFIED]** pinned Electron 43 `Clipboard` 类型只有同步读写、format/buffer 等方法，没有
clipboard change event、writer/source identity 或向外部应用粘贴的 API。`PowerMonitor` 和
`GlobalShortcut` API 存在，但 API 存在不代表已经形成 Product Plugin 可消费的 Core contract。

**[VERIFIED]** M1 文档明确没有实现 Package Gate、Capability Broker、隔离 Runner 的完整产品
能力；安全契约同时禁止 Product Plugin Client 直接调用 Electron/preload/native，Host 必须经过
Broker/provider contract。因此不能把 clipboard 逻辑直接塞进插件 Client 作为捷径。

### 同一 artifact 的推荐运行语义

**[INFERENCE]** 保持一个 Smart Clipboard Product Plugin artifact，不增加第二个用户可安装的
`smart-clipboard-native-macos` artifact：

| 环境 | 建议行为 |
| --- | --- |
| Hermit + 所需 Core capability | 同一个 Product Plugin 正常加载，业务 activation 成功。 |
| stock DSH 缺 Hermit native capability | artifact 安装和普通 lifecycle 保持健康；capability handshake 确定返回 unavailable，不启动捕获、快捷键或 native UI。业务入口如何表达 unavailable 取决于 G2 的正式 Product Surface contract。 |
| capability 运行中消失 | 立即停止 privileged operation，不删除 Canonical data；恢复策略由最小 lifecycle contract 明确。 |

native provider 属于 Hermit Desktop/Core，Product Plugin 只消费窄 capability contract。内部按
domain/host/client 拆源码不等于拆第二个安装 artifact。

这项建议与 `DESIGN.md` 当前“宿主缺能力时可预测地拒绝业务激活、不留下入口”的规则需要在
G3 精确解释：应拒绝的是 Smart Clipboard 业务 activation，而不是把整个插件包伪装成损坏；
在 Product Surface 尚未通过前，不提前决定 stock DSH 中 unavailable 的最终 UI 位置。

## 开发前 Gate

以下是进入正式业务实现前的依赖顺序，不等于所有 spike 必须串行排期。G2 未通过时，G3/G4
可以并行做可丢弃的 diagnostic/readiness spike 来消除平台不确定性；宿主无关的纯 domain 规则
可以先实现，但不能把 spike 直接固化为正式 ClipboardBridge、Core-owned domain DB、search 或
History 宿主实现。全程不预建 Windows/Linux framework、
通用 native provider 平台或完整第三方插件市场。

### External-0：Organizer 排期 Gate

沿用项目既有顺序：Organizer 第一条切片达到定义的稳定门槛后，Smart Clipboard 才进入业务
实施排期。它是项目排期 Gate，不是下列技术 Gate 的替代品。

### G1：Pasteboard 产品语义

需要产品 owner 确认下面这类明确规则：

> ACTIVE 表示插件已启用并立即尝试捕获；Hermit 不增加自己的首次 onboarding 或“开始记录”
> 门槛。macOS 仍可能显示系统权限提示。系统拒绝时，插件 lifecycle 可保持 ACTIVE，但 capture
> capability 显示 blocked/unavailable，不产生新历史；系统权限恢复后的恢复行为必须明确。

**影响：** 这不是要求增加 Hermit 隐私设计，而是承认 OS 无法被插件忽略。它会改变 ACTIVE、
denied 状态和验收文案，因此本调研不直接修改 `DESIGN.md`。

### G2：DSH Product Surface（stock 或 Hermit 受控 patch）

通过标准：frozen DSH public contract 允许插件 additive 地贡献全局业务入口和持久页面，且：

- 不替换 `sidebar` / `conversation` / `details` 第一方 occupant；
- 不借用 Settings、DOM、CSS selector、private router/import；若走 Hermit source patch，patch
  必须是底座构建输入，不能成为插件私有运行时依赖；
- 能在具备 Product Surface 的宿主上以同一个 artifact 打开、刷新恢复并按支持的 lifecycle
  撤销；另一宿主缺少该能力时仍能安装并确定性 unavailable；
- React/ReactDOM 仍保持单实例。

当前 stock `rc.2` 为 **FAIL**。用户已授权 Hermit 评估受控 source patch，因此 G2 不再只能等待
上游：在 patch qualification 未通过前，仍停止正式 TEXT domain/business implementation；允许
并行完成 G3/G4 的最小诊断 spike，但不发布、不接业务数据，也不把临时 seam 当成生产契约。

### G3：最小 Core capability seam

通过标准：同一个最小测试 artifact 只能通过 Core public contract 查询/消费本 slice 所需能力；
Hermit 返回真实 provider，stock DSH 返回 deterministic unavailable；Client 没有 Electron、preload、
AppKit/Win32/Wayland import。

diagnostic spike 中的最小 Core spine 只连接已经冻结的三条独立 contract：

- ClipboardBridge 仍严格只有既有的 `observe`、`snapshot`、`write`、`sourceIdentity`、
  `autoPaste` 五类能力；
- Shortcut Registry 单独负责全局快捷键 registration/result/dispose；
- Product Plugin activation lease 负责 generation 与 dispose。

字段应由 G4 真实平台结果反推，不先做通用 native 平台。后续资格审查已经否决“先做独立
Swift helper”作为当前默认方案：独立 helper 的 AccessBehavior/Accessibility 属于 helper 自己的
进程身份，不能冒充 packaged Hermit；General Pasteboard 的 lazy/promised/custom representation
及原 owner 生命周期也不能靠 bytes snapshot/restore 无损重建。当前只保留 qualification-only
Electron main provider；未来若真实生产 seam 证明必须有 in-process native 实现，再单独评审，
不因为消灭 UNKNOWN 提前创建 native framework。

### G4：packaged macOS clipboard

必须通过 G3 的真实 provider 路径，在 packaged Hermit + macOS 26.x 上验证：

1. AccessBehavior API 是否可读，以及 General pasteboard 在当前 packaged app 中是否实际执行
   `default/ask/alwaysAllow/alwaysDeny` 提示和阻断；
2. `changeCount` 观察、每 item type/marker 检查、TEXT representation 读取；
3. denied/无 payload 不入库，且可观察地报告状态；
4. 锁屏时 UI 关闭和 History 不可见；锁屏期间真实 capture 行为单独记录；
5. TEXT 写回系统剪贴板；
6. Accessibility allow/deny 下的 auto-paste 与 copy-only；
7. 全局快捷键成功、冲突返回 false、撤销和重新注册；
8. source app 误归因边界和 unknown/null 表达。

不能用模块测试、Electron 类型存在、未签名开发进程或 Maccy 的运行结果代替 packaged Hermit 证据。

### G5：artifact 与 lifecycle

通过标准：

- Hermit 中同一 Smart Clipboard artifact 获得 capability 并完成 activate；
- stock DSH 中同 artifact 能安装/加载，缺 capability 时确定性停止业务 activation 且不 crash；
- disable 后 capture、shortcut、timer/watcher 和 Host effect 立即停止，已有数据保留；
- Client UI 按当前明确的 restart/reload boundary 验收，不误报同进程 hot unload PASS；
- 若 Product Surface 或 DSH 版本变化，重新跑 reference artifact 双端、React 和 lifecycle 资格。

G1-G5 与 External-0 都满足后，才进入正式 TEXT domain DB/search/History/快速取回实现；G2
未通过期间形成的 diagnostic code 不属于这条正式实现。

## 首切片开始后仍应保持的范围

Gate 通过不扩大首切片：只做 TEXT 捕获、明确 marker 过滤、精确 Hermit 去重、持久化/重启恢复、
最小 History 列表/详情、快捷唤起、输入搜索、键盘选择、write-first auto-paste/copy-only、停用清理
和已冻结的真实限制。

**[INFERENCE]** 首切片最多 100 条普通 TEXT，普通 substring 搜索先用参数化 SQLite `instr`
即可，不需要为了未来 IMAGE/FILE_LIST 或复杂检索提前建设 FTS schema；后续完整 M1 若按核心需求
引入 FTS，它仍是可重建派生索引。由于核心需求当前写的是“SQLite/FTS 搜索”，正式实现前应由
需求 owner 明确该措辞是完整 M1 目标，还是要求第一条 TEXT slice 立即建立 FTS；本调研不修改
权威需求。快捷键事件到快速取回首帧可交互的性能门槛直接复用 Core 现有 warm 指标：100 次
`p95 <= 300ms`、`p99 <= 500ms`。qualification-only Electron 夹具已经按当前确认的鼠标附近
上下文菜单式浮层执行 100 次，实测 `p50 = 35.7ms`、`p95 = 47.4ms`、`p99 = 78.7ms`、
`max = 376.4ms`，同时通过输入搜索、键盘选择、Escape、锁屏模拟关闭、焦点恢复和屏幕工作区
收敛。该结果证明交互和桌面窗口策略可行，不等于 Product Plugin -> Core 正式 seam 已通过。

不要加入 IMAGE、FILE_LIST、Trash、导出、完整设置、AI、`@clipboard`、模板、知识库、OCR、
自动分类或后台加工，也不要为这些未来能力预建空状态和抽象层。
